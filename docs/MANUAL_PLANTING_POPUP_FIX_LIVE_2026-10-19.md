# 工作计划弹窗修复与默认入口实机尝试

## 代码与离线校验

`tools/manual_planting_ui.py` 在默认入口准备阶段优先识别正式资源中的工作计划标题，并要求底部“点击空白区域继续”模板一致，才通过原 Maa 后台输入在既有关闭点 `(360,1220)` 点击一次。随后重新截图，弹窗未消失就停止。地图变换函数也明确拒绝工作计划画面。

开种子栏改用正式种植原有的偏右25像素土壤点，避免原地块中心与员工交互区域重叠的可能；该点在开栏前也必须通过空土壤检查。没有改变默认缩放模型、地块映射或防重复规则。

新增真实工作计划弹窗截图回放，覆盖关闭成功、关闭失败不重试、关闭提示缺失不点击、弹窗禁止地图定位，以及开栏只点击已验证土壤侧点。手动种植相关54项离线测试通过。最初使用模块路径运行测试时有测试导入路径错误，随后改为项目已有 discover 方式完整运行。

## 实机结果：弹窗修复验证通过，种植验收未完成

所有尝试均通过真实 Maa `Resource/Tasker → ManualPlantingOnce → cycle_bridge → ui_worker → run_manual_planting.py` 默认链路，仅传农田2、番茄14、数量1；没有临时缩放、坐标或校准参数。没有运行连续循环。

1. 弹窗关闭修复后，第一次目标中心点击又打开工作计划；没有种植输入预留。随后只关闭已识别弹窗并截图，默认目标为农田2第2槽，约 `(512,605)`。
2. 增加土壤侧点检查后，正式入口成功打开第2槽种子栏并选中番茄。执行器已写入1条防重复预留，随后 `plant()` 内最后一次 `assert_soil()` 失败，尚未到达 `backend.click()`。实际种植点击0次。
3. 停止后截图可见种子栏、番茄选中及第2槽白框。稍后只读回放同一点约 `(537,605)` 土壤检查通过，因此可能为瞬时角色遮挡；由于没有失败瞬间截图，原因尚未证实，不能断言已解决。
4. 前后解码中农田2第2槽均为 `[0,0,0,986]`，作物、开始时间、生产轮次未改变。84个生产槽位的身份与原始元组一致，员工计划和库存数量一致。预计消耗0金币，缓存未提供金币余额，不能独立验证其余额变化。
5. 第一格未确认成功，未执行农田3，也没有点击其他生产槽位或收获。保留 `unconfirmed` 日志及预留标记，未解除防重复锁，未再次运行种植。

此结果不能标记为“农田2、3种植验收通过”。尚需处理/明确最终土壤检查的瞬时遮挡，并按持久防重复记录进行人工核对后，才能安排下一次实机验收。
