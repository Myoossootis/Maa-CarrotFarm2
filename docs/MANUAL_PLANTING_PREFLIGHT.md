# 手动种植：Maa 配置接入和只读预检

2026-10-18。本轮只接入配置、计划和校验，未执行游戏操作、未启动循环。

后续更新：2026-10-19 已新增独立的“手动种植（单次）”代码入口；本页原只读入口保持不变。执行范围、定位限制和离线验证见 [Maa单次接入](MANUAL_PLANTING_MAA.md)。

## 使用入口

Maa 新增独立任务 **手动种植（只读预检）**，默认不勾选，支持：

- 农田1、农田2、农田3。
- 番茄、小麦、玉米、甘蔗、土豆、玫瑰、胡萝卜、草莓、白菜、水稻、红薯、辣椒。
- 种植格数 1–36，仍受所选农田实际空位限制；这是格数，不是产品数量，也不乘以6。

入口 `ManualPlantingPreflight` 注册于 `agent/main.py`，没有后继执行节点。
`agent/manual_planting_action.py` 只读解码并打开带预选参数的数据窗口。
没有 `apply`、执行按钮或执行开关；未知执行参数会被拒绝。
`tools/prepare_maa_ui.py` 已允许此任务；本机 `.tmp/maa_ui/interface.json` 和实例任务定义也已更新，
新增任务保持默认不勾选，原文件备份在 `.tmp/manual_planting/maa_backups`。
没有重启现有 Maa 或启动其任务队列；已打开独立数据窗口。现有 Maa 若缓存旧任务列表，需下次重新加载配置后才能看到新入口。

单独运行只读预检：

```powershell
.venv/Scripts/python.exe -X utf8 tools/manual_planting.py --field field_1 --crop-item-id 14 --count 1
```

输出在 `.tmp/manual_planting/current_state.json`、`preflight.json`。
预检通过退出码0；条件不足或读取失败返回2。返回0也不会种植。
已有数据窗口新增“手动种植预检”页，可选择农田、作物、数量，查看空位、拟用槽位、费用和阻断原因。
参数改变仅计算本地快照，点“只读刷新”才读取新缓存；手动种植页固定用 automation 模式，不扫描狮王任务。

## 操作前后解码校验

代码在 `tools/manual_planting.py`，没有控制器或鼠标输入依赖。

`build_preflight` 检查只读来源、包87规则、新鲜度10秒、完整槽位、目标建筑唯一性和员工归属；
有员工目标、累计产量、待领取产品或未完成操作时阻断。
只使用已解码空位，不会清地、收获、扩地、换员工或自动改计划。
COMMON_STORAGE 87 对应的一键全区域模式必须明确关闭，防止一次操作影响多个农田。
收费余额不足或未知、作物未解锁、未知配置均不报告可用。

`validate_before(plan, current)` 要求重新读取快照；新状态必须与原计划绑定的库存、员工计划、
建筑/载体身份、原始槽位、费用和缓存序列一致。变化即拒绝，不偷偷重排计划。

`verify_after(plan, before, after)` 只比较两份解码快照：

- 操作后快照必须较新，规则版本和员工计划保持一致。2026-10-19农田2实测表明，槽位原始元组可先于 storageSequence 变化，故序列号只作记录，不能单独作为成功或失败依据。
- 变化的物理槽位必须恰好等于计划槽位集合，不能只比较总数。
- 每个目标从空位变成所选作物的正常或允许变异输出，计时开始且生产轮次标记变化。
- 可观测的消耗余额扣除必须与预期完全相符。
- 原始槽位未变返回待更新；部分成功、多种、错误作物、轮次未变、扣费不符均返回失败。此纯校验函数不轮询、不点击；执行器只对待更新结果做有界只读等待，不补点。

当前 Maa 路径只调用预检，不调用执行器；操作前/后函数为后续单次种植执行接入提供校验边界。
2026-10-19 已另外完成农田1第1槽番茄1格的单次实机验收：只有目标槽位变化，轮次1135→1136，点击后3.746秒读到缓存更新。正式 Maa 入口仍只做预检，未启用通用执行器。详情见 [单格实机验收](MANUAL_PLANTING_LIVE_ACCEPTANCE_2026-10-19.md)。收费作物的实际金币扣费仍未验收。
