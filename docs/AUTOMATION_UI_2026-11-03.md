# 独立自动化主界面验收

日期：2026-11-03，UTC+8。版本0.13.0，主题分支`codex/automation-task-controls`。

## 行为与执行边界

新界面替代MFAAvalonia作为日常入口。双击`启动萝卜家园自动化.cmd`；原`启动Maa界面.cmd`和PowerShell入口也转入新界面。仍使用MaaFw 5.13.1、现有本地只读解码和视觉后台输入。没有恢复Cocos／Frida／WMPF内部调用。

开始会校验并保存当前表单，生成独立运行ID和冻结请求，随后启动现有任务执行器；无需返回Maa任务列表。修改正在运行模板的表单不会改变本次冻结配置。打开主界面只读数据，不自动开跑。

暂停在输入安全边界等待，点击和拖拽先完整释放并恢复窗口可用状态；继续使用原进程与运行ID，不重建任务。所有输入工作进程确认暂停，或尚无输入工作进程时显示暂停。程序初始化和只读版本检查可继续并报告阻塞。暂停保留共享锁，不能用另一个窗口同时写游戏。游戏生产仍继续，恢复后沿用即时解码及原有超时／未决守卫。

结束请求直接传到本次所有后代；保存计划和业务意图保留。关闭主界面同样停止本次任务。合作停止超时只清理本次拥有的进程树；缺少有效结果、异常退出或退出码冲突均显示未确认／受阻，不宣称业务完成。不会终止微信、游戏或其他窗口的任务。

聚会／外卖次数语义目前仍只核对客户端90；客户端98在打开订单页前阻塞。普通订单与员工生产保留90／98原有核对范围。手动种植保留原预检与历史未决保护，不因换界面而放行。

## 普通3倍停止与恢复

开始前即时解码：旧员工操作已收取、旧订单完成且已返回农场；员工记录没有目标或待领取产物。当前订单缺苹果8、玫瑰23，原有无关计划未被覆盖。

第一次有限测试通过新界面启动、暂停、同进程继续，保存农田1玫瑰23后，在果园1保存前编辑中结束。原恢复守卫正确保留未决编辑。修复仅针对这个可证明未发保存的状态：关闭已识别旧草稿，确认员工／建筑身份、空计划、物理空位及重复模式，并重新核对原订单与库存；原编辑另存证据后才建立新编辑。`save_intent`／已保存计划／收取日志不走该分支。

第二次从新界面开始，同一生产操作恢复：农田1直接回读，不再打开保存；果园1只恢复未保存部分，果园2正常保存。即时解码确认农田1玫瑰23、果园1苹果4、果园2苹果4，均为一次性计划；没有剩余`editing`状态。全部保存后结束，工作进程退出、共享锁释放，计划保留供下次开始接续。本轮没有交单／领奖，不计完成订单。

原始快照、截图、临时GUI验收脚本和运行记录仅在本地`.tmp/automation_ui_2026-11-03/`；正式运行记录在`.tmp/hud_runs/`。源业务记录仍以`.tmp/employee_operations/active.json`与普通订单回执为准，不能按旧截图或本报告直接发送业务输入。
