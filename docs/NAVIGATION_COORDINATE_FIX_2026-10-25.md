# N01：裁剪截图坐标修复（0.7.1）

日期：2026-10-25（UTC+8），分支 `codex/navigation-frame-coordinates`。

## 复现与根因

上一轮实机停在“餐厅就职”：灰色农场帽模板定位成功，后台点击有回执，但页签没有切换。读取截图和输入换算代码，确认 `normalize_frame` 把720×1399原始截图裁成720×1358，记住顶部裁剪41像素，却把缩放分母也改成1358。

输入先通过 `to_controller_xy` 恢复顶部41像素，再通过 `_screenshot_to_client` 按1358缩放，相当于重复放大高度。归一化页签中心(535,1238)恢复到原图应为(535,1279)，旧代码在同尺寸窗口得到(535,1317)，向下偏移38像素。在本机318×618客户区，正确目标为(236,564)，旧逻辑约为(236,582)。这能解释底部页签失效，而不是先归因于动画或加重试。

修改仅让输入换算保留原始截图宽高；截图仍裁成原有模板尺寸，顶部裁剪仍只恢复一次。点击和滑动共用该修复。未改模板阈值、没有新增重发、没有恢复Cocos／Frida／WMPF方案。

## 验证

- 修复前：4项新坐标回归中3项失败，复现y=1317而非1279。
- 修复后：4项坐标回归通过，覆盖1399／1410带裁剪截图、1348／1358／1370无裁剪截图、不同比例客户区、连续捕获更新以及真实点击／滑动换算链。Win32分发被mock，不操作游戏。
- 原有后台输入13项通过，继续验证只向唯一渲染子窗口发消息、不移动实体鼠标、取消时释放鼠标。
- 完整回归Python510项中507通过、3项因可选旧截图缺失跳过（34.285秒）；Node23项通过，版本一致性与差异检查通过。
- 实机：农场→员工列表→农场连续3次；专门切到餐厅就职后，灰色农场帽→农场列表→农场连续3次。第二组每次只点击一次农场页签，均确认选中。
- 每轮对比全部9个岗位的建筑、员工及目标配方，均未变化。没有种植、收获、换人、排产、交单或付费操作；已有生产保留。
