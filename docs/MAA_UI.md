# Maa 界面使用（产品化）

> 当前版本0.13.0（2026-11-03）：主入口已改为「萝卜家园自动化」，无需返回Maa任务列表。默认普通3倍模板，点击开始保存当前配置并运行；暂停后可同进程继续，结束和关闭窗口会停止本次任务并保留计划。逐模板验证及实际限制见[AUTOMATION_UI_2026-11-03.md](AUTOMATION_UI_2026-11-03.md)。

双击根目录`启动萝卜家园自动化.cmd`。旧`启动Maa界面.cmd`／`.ps1`也打开新界面，不再启动MFAAvalonia。打开窗口只读数据，不自动运行任务。

在「自动运行设置」选择模板，填写参数后直接点击开始；「保存配置」只保存，不执行。运行区域显示本次日志、缺口、生产进度和阻塞原因。暂停保留进程与共享锁，点击继续沿用同一次运行；期间游戏生产仍继续。结束不会清理在产计划，下一次开始须按实时数据和原回执接续。预览模板只预览步骤；输入前被规则或版本拦截时显示受阻，不能当作业务完成。

## 模板自定义（0.12.0）

在「自动运行设置」选择模板，右侧编辑本模板选项并点击「保存配置」，或直接开始保存并执行。当前运行任务沿用启动时的冻结参数。各模板相互独立，普通订单的一号位选择不会改动聚会／外卖选择。「设置」页也可选择订单模板修改一号位品类。

| 模板 | 可调整配置 |
| --- | --- |
| 聚会与外卖、聚会、外卖、普通一轮 | 一号位允许的24种品类 |
| 普通3倍持续 | 一号位品类、完成订单单数（0表示持续） |
| 手动种植、手动种植预检 | 农田、作物、种植格数 |
| 刷新指定订单 | 订单类型、位置1–9 |
| 饲料生产 | 背包饲料暂停上限、检查间隔 |
| 单订单扫描预览、单订单补产交单 | 轮数、检查间隔、监控超时 |
| 单订单补产与交单（高级） | 预览／正式模式、轮数、间隔、超时 |
| 关闭离线收益 | 无可调整参数 |

未保存时从现有Maa实例读取选择，包括自行新增的小麦等品类；「恢复默认」只填入默认值，点击保存后才生效。「改用Maa选项」移除本模板的本地覆盖，恢复使用任务列表里的勾选。优先级为：本模板本地保存 > 当前Maa任务选项 > 原默认值。保存文件为本地`config/task_settings.json`，不上传仓库；损坏或未知版本时停止任务，不默认为空选或成功。客户端、生产与收取的既有保护继续生效。

## 一号位订单启动规则（2026-10-16）

聚会、外卖、普通订单正式任务启动后，先识别对应页签的 **一号位**，再检查配额、排产、交单；联合调度先检查两类一号位。交单领奖后进入下一轮时，再次检查新的一号位。

在各日常任务的 **一号位允许品类** 多选框中选择品类，图鉴全部24种均可自选，**勾选表示允许**。默认勾选：**苹果、番茄、水稻、玉米、甘蔗、土豆、玫瑰花（图鉴名「玫瑰」）、牛肉、鸡蛋**。各任务按自身勾选生效；新增勾选可放行，取消勾选即排除。水稻与小麦是不同作物，小麦默认不勾选，可手动加入。全部取消时启动前提示至少选择一种。默认值读取 Maa 配置，不在业务代码中固定排除。

一号位出现任意未勾选品类，即更换该张并点击 **免费加速**，重新识别直到符合。**菜品等级太低、无法接受**也走同一免费刷新流程，不点升级。其他位置保持原选择逻辑。日志记录本次勾选的品类，并传给启动检查、联合调度及交单后下一轮检查。

多选接入验收：310项回归通过；真实 Framework → Agent → 预览 worker 分别验证默认九类、自选猪肉/辣椒及空选拒绝，日志为 `.tmp/first_order_policy/preferences_ipc.log`，回归日志为 `preferences_regression.log`。本机 Maa 的任务缓存和界面配置已同步，完全退出后重新打开即可加载多选框。

识别失败重读最多3次并记录错误；现有交单无法处理的超出可见区域长配方，因无法核对完整白名单而免费刷新。已有进行中/待领奖订单交回原领奖流程。单次检查最多免费刷新50次，仍不符合则明确报错，联合任务继续检查另一类型。预览模式不识别、不刷新游戏订单。

日志与每轮前后截图：`.tmp/first_order_policy/<类型_时间>/`；结果含原品类、白名单外品类、菜品等级不足原因、刷新次数，以及失败阶段/堆栈。工作进程及子步骤日志沿用 `.tmp/worker_logs/`、`.tmp/step_logs/`。

图鉴新增 `crop_023` 水稻、`crop_024` 辣椒；红薯复核沿用 `crop_011`，旧ID保持不变。新模板来源为用户确认的种植菜单后三项与本机720宽截图；新作物员工补产能力仍需在员工工作计划中验证，未因玩家解锁而自动放开员工能力。

实机验收：普通一号位最终为苹果/甘蔗，聚会为番茄/玉米/鸡蛋，外卖为番茄/玉米/牛肉，三类均正确放行；外卖多次出现菜品等级不足时已验证更换与免费加速。最终结果见 `.tmp/first_order_policy/live_result.json`；连续刷新过程见 `.tmp/worker_logs/20261015T231633630326Z.log`，该轮最终遇到 OCR 合并文本框问题，已修复后重新放行成功。Maa 日常 worker 持有运行锁时，启动真实子 worker 检查两类订单成功（`.tmp/first_order_policy/startup.log`）；此启动验收在排产前结束。301项回归通过（`.tmp/first_order_policy/regression.log`）。

## 单张订单刷新

勾选 **刷新指定订单**（默认不勾），在任务选项中选择 **聚会订单 / 外卖订单 / 普通订单**，填写位置 **1–9**（从左到右、从上到下）。只测试刷新时，取消勾选其他日常订单任务，可保留 Agent 连接检查。

执行：选中目标卡片 → 更换订单 → 如有稀有订单确认则确认 → **免费加速** → 确认指定位置出现新订单。目标已在刷新等待时，直接免费加速，不再次更换。刷新即刻完成，不等待倒计时。进行中、待领奖或不存在的位置不会更换其他卡片。

已同步本机 `.tmp/maa_ui/interface.json`；重新打开 Maa 加载任务。完整工作进程日志在 `.tmp/worker_logs/`，刷新前、加速前、刷新后截图及结果在 `.tmp/order_refresh/<时间>/`。失败记录阶段、异常堆栈与 `failure.png`；点击后停止会保留 `replace_clicked` / `free_accelerate_clicked`，便于确认当前状态。

2026-10-16 验收：普通、聚会、外卖第1张均通过真实 Maa Framework → Agent → worker → 游戏的完整更换与免费加速流程，结果为 `refreshed`；三类等待中订单的续加速也通过。实机日志 `.tmp/order_refresh/agent_live.log`，续加速日志 `resume_agent_live.log`；277项回归测试通过（其中14项刷新测试），日志 `.tmp/order_refresh/regression.log`。稀有订单确认分支为模拟测试，本次实机未遇到确认弹窗。

## 前台安全点击

业务点击只走 `post_click_normalized`（渲染子窗 PostMessage，**不发 WM_ACTIVATE**）。  
`interface.json` **不暴露**原生 Click/Scroll 任务；订单/背包/告示牌由短循环 CustomAction → `ui_worker` → CLI 模板点击完成。  
pipeline 里仍保留历史 Click 节点供识别模板，但 UI worker 禁止对它们 `post_task`（仅允许识别节点 `VerifyNormalOrderInProgress`）。详见 [FOREGROUND_SAFE_INPUT.md](./FOREGROUND_SAFE_INPUT.md)。

## 正式执行与停止

- 正式任务 / 「正式执行」选项会弹清地确认；取消则不启动 worker。
- 「停止任务」会发取消信号；**已保存的员工计划不会自动清空**。停止优先于继续上次未排完的工作。
- 默认预览不会点游戏、不弹清地确认。
