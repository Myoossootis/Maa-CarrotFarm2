# 狮王选取、升级与刷新

2026-11-05（Asia/Singapore），应用0.16.0，客户端100，分支`codex/lion-task-acquisition`，基于0.15.1。Cocos／Frida／WMPF实验继续封存。

## 使用方式与交付边界

新主界面“自动运行设置 → 狮王选取／升级／刷新”直接开始、暂停／继续、结束。默认只选20礼券，提供2／20多选；多选时优先较高档，较高档超余额／剩余预算时仅可退到明确勾选的较低档。默认最多20次刷新、总礼券预算600（包含升级），可修改；中断恢复沿原配置与预算，不因重启补满。

此模板选好**一个**任务后返回农场；“选取完成”不表示任务条件或领奖完成。当前已有执行器支持的苹果UP优先于其他同类合格候选。随后从同一界面的“本人已接苹果UP（一任务）”继续生产／收取／领奖；执行记录位于本次选取目录的`execution/`，不替换0.15.1已完成的旧回执。黄桃、鸡蛋、牛肉和餐厅UP可以判断是否满足选取规则，但对应条件执行器仍需后续接入；未上阵的已拥有员工也不会静默换人。

本期目标仍为26。当前只确认单次领奖扣减契约，历史本期已完成数仍不能由3956余额推断；不宣称整期自动循环已完成。

## 策略

1. 优先本人已有任务，不接第二张。历史本人任务不符合新策略时保留，不擅自刷新或放弃。
2. 排除他人接取、他人已升级但未接取的预留，以及冷却槽位。预测升级后的任务，而非用升级按钮费用作奖励。
3. 最终条件必须是拥有指定员工的UP，最终奖励≥80铃铛；所有餐厅星级任务不选，包括32星、102铃铛。指定员工只需按任务要求保持上阵，生产人员不必是该员工。
4. 没有合格候选时，才接取已识别且未预留的垃圾任务。没有足额刷新预算／礼券时先停止，不接一张无法刷新的垃圾任务。未知条件不当成普通垃圾。
5. 刷新后重新评估；青苹果35铃升级为70铃，仍不执行。高铃铛星级任务直接保留，即使游戏“今日不再提示”已生效也不再刷新；若高铃铛提示已显示，点击取消，再退出留给家族。其他已识别垃圾任务的同类提示可以确认。
6. 退出保留该槽任务内容、升级信息及服务器进度，当前运行跳过该槽，寻找下一张。120秒只限制再次退出，不限制接取；需要再次退出时读取个人3921.extra.cd与当前时间等待。

## 读取与输入契约

- 包100升级费用为`min(2×当前铃铛−2, cfg_items5554.limit)`，当前上限136；费用优先4030礼券，不足时客户端会切珍珠。因此脚本余额不足即停止，并要求升级确认文案中的礼券、费用和最终铃铛都一致。
- 最终奖励读取`mutation_id → cfg_task.reward_box_id`。甘蔗21→42（费用40），青苹果35→70（费用68），32星51→102（费用100）；不能把40／68／100当作升级后的铃铛。
- 刷新档位来自当前3921等级对应的`cfg_level(type7).params.datas`，从index4读取(box,cost)对。2档随机，20档≥35铃，不保证UP或80铃。面板左侧文案固定写“珍珠”；实际按钮会随余额切换币种，支付必须识别礼券图标和对应2／20数值，并有新解码余额证据。
- 普通收获为单条件`687,1,产物,数量`，UP为已核对3944条件，星级为3949。新类型／复合条件不猜测。
- 每次接受、升级确认、刷新档位支付、退出确认前落盘意图；动作后要求本人／家族／期数／包一致、共享槽UID一致、个人实例已同步、3956不变、珍珠不变及礼券恰好扣费。升级／刷新后重新定位个人任务UID，不能假定沿用旧UID。
- 结果不明时只回读，不重发。刷新随机得到同ID且个人UID也不变时，目前缺少独立服务端事务标识，明确停止，不靠扣费单证继续刷。
- 重启先补证未决结果；尚未支付的已识别升级／退出确认或刷新档位面板先取消／关闭，再导航。未知弹窗不盲关。输入复用原Maa截图和后台消息模块，共享单写入者锁。

静态规则只证明客户端代码／配置。静态原件与REA证据保留本地，父Evidence `ev_9b9b30653729d06a93230cb4360915c7e411b4a72ae2726da8f5e4a5ab30d34d`；没有执行游戏JS或发送内部请求。
