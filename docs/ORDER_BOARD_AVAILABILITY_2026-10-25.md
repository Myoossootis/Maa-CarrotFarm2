# 0.7.2 订单板前检验

日期：2026-10-25（UTC+8）。路线：本地只读解码＋Maa视觉和窗口消息输入；未接入封存实验。

## 复现与修复

0.7.0的聚会失败截图显示0/6、九个卡片为空，但缓存仍有旧订单。原流程直接选卡并检查完成次数，最终报“Single completion control is not confirmed unchecked”；短循环还能重复扫6轮。截图只证明那一刻没有卡片，不足以解释原因。

本轮实机首先看到了空板，紧接着同一页签就出现有效卡片。两种画面都保留“已达每日恢复6次上限”的OCR读文。该提示和0/6不能用于证明已耗尽接单额度、重置配额或推算冷却。

新增共享前检验：先确认正确页签和截图规格，再以九个卡片区域分别与空背景对照，并识别当前卡片及提示。最多读取3张新截图，中间间隔0.5秒，期间不点卡片。有效卡片出现即进入原有选卡和解码核对；连续3帧空板且提示一致才返回`board_unavailable`，原因仅记为`confirmed_empty_board`。明确加载或尚未稳定时返回`board_loading`；证据不全、错误页签和冲突状态返回`board_unknown`并停止。

入口的一号位白名单检查与批量订单执行共享该检查。等待状态没有目标，不触发排产或接取；短循环停止本轮，日常调度保留原因，让其他类型继续，没有可信时间便不自动重试。既有接取意图和配送凭据保留，等待不记配额，不代表完成订单。

## 验证范围

- 新回归先复现选卡前缺少保护及6轮重复扫描，再验证无选卡／刷新／接取、旧配送凭据不变、等待没有生产或配额收据、没有猜测恢复时间。
- 真实Maa OCR回放去除身份、货币、库存和配方的静态截图，覆盖持续空板。另以模拟后续帧覆盖“先空后出现卡片”、提示变化、持续加载和每个位置存在卡片；这些是离线验证。
- 实机打开聚会和外卖，均读到有效卡片，即使同样显示0/6和上限提示也没有误报不可接。之后返回农场，前后员工UID、建筑和计划目标保持一致。没有接单、扣料、收取或购买。
- 通过正式`ui_worker → complete_batch_orders --prepare-only`复测，在连接阶段被旧保护`nonzero screenshot offset is not validated`阻塞，未到选卡。该问题记作N01b，不能将本轮只读验证代替正式选卡、配方、完成次数或业务闭环验收。

离线完整回归：Python共523项，520通过、3个可选历史截图用例跳过；Node23项通过；资源与界面Schema、maa-tools、版本0.7.2及diff检查通过。新增12项看板回归与1项短循环等待回归；单独运行短循环测试也通过，避免依赖其他测试对导入路径的修改。

## 剩余限制

持续空板的实机恢复时间和原因仍未知；它可能继续加载，等待状态只结束本次扫描，不能记为额度耗尽。识别仅支持当前已验证的720×1358归一化布局，其他布局和不匹配背景仍阻塞。N01b修复后须补正式选卡验收，再推进N03操作恢复日志和后续员工闭环。UP手动一键种植／收获仍未实现，本版本不声称已支持。
