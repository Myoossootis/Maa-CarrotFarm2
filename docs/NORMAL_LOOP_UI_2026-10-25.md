# 普通订单3倍循环 UI 与实机记录

日期：2026-10-25。0.8.2恢复底座提交后，0.9.0接入独立Maa任务入口。

## 0.9.0 交付范围

- 新入口“普通订单3倍持续循环”，默认不勾选。完成订单数0为持续，1–999为本次运行的有限单数，每单3次。沿用一号位允许品类，点击停止保留操作日志。
- 新运行先恢复绑定生产：未保存部分重新核对后处理，已保存部分跳过编辑／保存，收取必须属于同一操作；完成后重新扫订单和库存。普通单未决回执优先恢复，不能新接取。
- 缺料使用空闲员工；建筑、员工、目标或状态变化时停止。已有在产计划、牧场2待领及历史未决记录保留。饥饿补饲、未知弹窗等未验证情况阻塞，不伪造持续成功。
- 原普通订单单轮入口保留。Maa的轮数配置替换整组custom_action_param，因此覆盖同时保留订单类型、continuous及轮询参数；真实Resource回归验证这一点。

## 0.9.1 对账与修复

奖励层的初始判断已修正：后续回读发现同一槽位UID仍为原UID、状态已回到待接，但配方改变；该槽位会复用UID。首单奖励实际上已到账，旧日志没有覆盖领奖导航，不能以“未调用显式领取按钮”推断没有领奖。

新路径在可能触发直接领奖的导航前写reward_intent；出现已知奖励层就停止导航，不再尝试其他入口。关闭已识别奖励层后回读待接状态；有新意图且结果已确认时，重启可以只读完成回执，未确认仍不再点击。旧未绑定reward_intent保持阻塞。

另外修复本轮回归发现：启动前已completed的旧回执不得作为本次新完成返回；仅本次恢复得到的completed可计入。订单板淡入时第一张卡片短暂半透明，增加有限只读观察，不重发选卡。
