# 普通订单3倍循环 UI 与实机记录

日期：2026-10-25。0.8.2恢复底座提交后，0.9.0接入独立Maa任务入口。

## 0.9.0 交付范围

- 新入口“普通订单3倍持续循环”，默认不勾选。完成订单数0为持续，1–999为本次运行的有限单数，每单3次。沿用一号位允许品类，点击停止保留操作日志。
- 新运行先恢复绑定生产：未保存部分重新核对后处理，已保存部分跳过编辑／保存，收取必须属于同一操作；完成后重新扫订单和库存。普通单未决回执优先恢复，不能新接取。
- 缺料使用空闲员工；建筑、员工、目标或状态变化时停止。已有在产计划、牧场2待领及历史未决记录保留。饥饿补饲、未知弹窗等未验证情况阻塞，不伪造持续成功。
- 原普通订单单轮入口保留。Maa的轮数配置替换整组custom_action_param，因此覆盖同时保留订单类型、continuous及轮询参数；真实Resource回归验证这一点。

## 验证与当前边界

离线全套570项、567通过及3项可选截图跳过；Node25项通过，schema与版本检查通过。随后补充未知版本和锁冲突回归，相关17项通过。预览不连接游戏，取消和重复回执不计入完成单数。

实机通过源pipeline与界面原生选项启动RunNormalOrderLoop，有限上限2。先中断等待中的独立监控，再由Maa任务入口恢复原绑定操作，未重复排产。农田1／2甘蔗计划20／21均实收，库存甘蔗10→52；计划清空、收取日志confirmed，农田3原计划保留。随后自动扫描并接取原普通单，苹果97→64、甘蔗52→1，精确符合3倍消耗，订单UID对应accepted回执。

本版实机停在领奖导航：完成时自动出现已知“恭喜获得／点击空白区域继续”层，open_normal_orders被遮挡而停止；未发领奖点击，未重接单，循环完成计数0。下一修订先补已知层的关闭校验，再从同一accepted回执恢复；本版不宣称一单或连续两单闭环通过。
