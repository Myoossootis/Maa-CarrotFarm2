# 狮王连续循环与实机验证（0.17.0）

## 行为与边界

新界面“自动运行设置 → 狮王连续循环（收获UP）”串联候选、接取、升级／刷新、分批排产、收取、领奖、贡献计数与下一任务。优先接续本人任务，其次只选最终至少80铃铛、指定员工已在农场上阵、产物与岗位已有执行能力的收获UP。餐厅UP、鱼类、自动换人及手动一键生产本版不启用。其他成员占用或升级预留均排除；高铃铛星级垃圾刷新结果保留给家族，沿原退出冷却逻辑处理。

默认20礼券档，保留2／20多选；600礼券预算含升级，20次刷新是整个循环总限额。每轮费用从已确认动作累加，恢复不清零。可提高原任务／费用／刷新总上限，不能降低或切换原档位。达到本期26、指定本轮任务数量、次数耗尽即停止；不购买次数、不用珍珠或加速资源。限额耗尽、身份／期数变化、截止时间到达、未知支付或领奖结果明确停止并保留记录。

## 恢复与生产保护

- `.tmp/lion_loop/active.json`指向当前循环，`loop.json`保存身份、赛季结束时间、轮次、累计计数与费用。每轮选取／执行回执独立保留，不能删除指针或重放旧完成回执来恢复。
- 首轮可接续0.16已确认选取及其80礼券花费，旧0.15完成任务不计入本循环。以后每轮分别保存个人任务UID及物理槽位证据，下一任务不会沿用上一任务的实例。
- 当前个人MMKV实例用于继续已绑定任务；其他共享槽位的堆缓存冲突不会阻塞本人生产。冲突槽位明确标记未知，不猜测哪份记录更新，也不作为可接候选。未知本人在途任务仍阻止新接取。
- 接受前再次核对任务条件、铃铛、接受按钮与升级提示；提示存在他人或未知升级人时不接取。已升级候选缺少本人升级提示证明时停止。
- 按当前可用岗位及编辑器容量分批生产。忙碌、在产或未决岗位保留等待；保存与收取仍复用已有意图和精确回读。上一任务存在未决生产时不进入下一任务。
- 领奖先保存意图，个人终态、3956恰减1、铃铛恰增任务奖励、2739代理5740恰增1后才确认。恢复不重复点击。贡献页返回后，本期次数必须恰增1、积分恰增该奖励，才记完成并开始下一轮。
