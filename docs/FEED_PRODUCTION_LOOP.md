# 饲料生产循环

Maa 任务列表最后新增「饲料生产循环（农田3）」，默认不勾选。设置项为背包饲料暂停上限（默认120份）和检查间隔（默认60秒）。将它放在其他任务之后，启动后持续运行，点击 Maa 停止结束。

循环固定使用农田3，安排玉米20、甘蔗16、土豆12，合计48，取消「工作完成后，继续使用当前计划」。已有其他计划时拒绝覆盖，也不重置待领物资。重启时读取检查点，继续监控本循环保存的计划。

每次检查先读取背包物资页的「饲料／已拥有」数量，再定位员工配置→农场就职列表底部的磨坊员工。待领数量两次一致且大于零时，确认黄色领取按钮后只点击一次，随后核对产出计数清零及背包数量。农场员工自行消耗背包饲料；本功能不操作动物喂养。

农田领取必须玉米、甘蔗、土豆三项分别满足完成量≥目标，目标分别为20、16、12。按用户确认规则，红皮土豆以1:1并入土豆完成量：普通土豆10/12加红皮土豆2，按12/12判断，直接领取，不另行补产。已确认的变异映射保存在 `assets/catalog/feed_mutations.json`；未知品类不抵扣。识别日志保留普通量、变异量和合计量，两次检查三项全部完成后才允许领取。单项完成、合计数量、出现黄色领取按钮，都不足以放行。

农田领取后，定位并打开磨坊，确认标题，勾选「一键补满」，确认材料和空余生产容量后点击补货。剩余可生产时间增加才确认补货成功，再安排下一批农田计划。材料不足或磨坊已满则等待下次检查；等待时返回农场，以便员工继续工作。

背包数量≥上限时暂停新排产、农田领取、磨坊领取和补货；继续定时检查库存，低于上限后恢复。已安排的游戏生产会继续，脚本不取消它。上限是暂停阈值，领取整批饲料可能略微超出。

## 日志与恢复

- `.tmp/feed_production/state.json`：当前农田阶段、是否待补货、背包读数、上限暂停标记和待确认动作。原子写入，停止不清空。
- `.tmp/feed_production/latest_run.json`：最近一次运行的日志与截图目录。
- `.tmp/feed_production/<UTC时间>/events.jsonl`：启动参数、每轮库存、各作物进度、暂停、动作开始/完成、等待、取消与错误。
- 同目录 `vision.jsonl`：OCR原文、匹配分数、坐标；`*_latest.png` 保留各识别阶段最近截图，避免无限累积图片。
- 同目录 `error.log`、`failure.png`、`observation_error_*.png`：完整异常与现场。普通识别失败最多连续重试3次；前台变化单独记录后继续核对游戏结果，不据此重发输入。
- 同目录 `cancelled.log`、`stopped.png`：用户停止的记录与现场，和执行错误分开。
- `.tmp/worker_logs/`：Maa Agent 启动的完整工作进程输出，包含参数、退出码及取消状态。
- `.tmp/mill_navigation/`：每次磨坊定位、点击、标题确认与失败证据。

动作前先保存 pending，确认结果后再提交阶段。若在保存计划、领取或补货期间中断，结果可能已经发生；下次启动会明确报告待确认动作并停止，避免盲目重复。需结合对应截图和日志核对现场后处理检查点，不应直接删除检查点强行重排。
